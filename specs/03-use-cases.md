# 03 · 用例模型 Use Cases（指导书步骤 1）

## 1. 参与者

| 参与者 | 说明 | 泛化关系 |
|---|---|---|
| Reader 读者 | 抽象参与者，持有借阅证 | — |
| Student 学生读者 | 本科生 / 研究生 / 博士生 / 专科生 | 泛化自 Reader |
| Teacher 教师读者 | 教师 | 泛化自 Reader |
| Librarian 图书管理员 | 读者的代理，办理借书、还书、查询 | — |
| SystemAdmin 系统管理员 | 系统维护 | — |

读者分四类（专科生、本科生、研究生、博士生）与教师，共五类，**借阅数量与期限各不相同**（BR-006）。
在用例图中统一用 Student 与 Teacher 表示，读者类型差异不单独立用例，而是作为**借阅规则**在
"检查借阅规则"用例中体现——避免用例爆炸。

## 3. 重点用例详述

### UC-101 办理借书 ★核心

- **主要参与者**：Librarian 图书管理员
- **次要参与者**：Reader 读者（被代理）
- **前置条件**：图书管理员已登录；读者已持有有效借阅证
- **后置条件**（成功）：生成一条 Loan 记录；对应 LibraryItem 状态变为 ON_LOAN；读者在借数量 +1
- **关联需求**：FR-006；业务规则 BR-002、BR-004、BR-005、BR-006、BR-007、BR-013

**基本事件流**

1. 学生找到欲借图书，将借书证与图书交给图书管理员。
2. 图书管理员输入**借阅证号**。
3. 系统验证借阅证存在（执行 UC-901 验证借阅证）。
4. 系统检查该读者的借阅规则（执行 UC-902 检查借阅规则）：
   a. 在借数量是否已达该读者类型上限；
   b. 是否存在超过规定借阅期限而未归还的图书。
5. 系统显示借阅者信息（姓名、系别、读者类型、在借数量、可用额度）。
6. 图书管理员输入**馆藏条码**。
7. 系统验证该副本为本馆藏书且状态为"在馆"（BR-007、BR-008）。
8. 系统创建一条借阅记录：借出日期 = 今日，应还日期 = 今日 + 该读者类型借阅期限（BR-006）。
9. 系统更新副本状态为"已借出"，更新读者账户在借数量。
10. 系统向管理员显示借书成功与应还日期。

**备选事件流**

- 4a. 在借数量已达上限：系统提示"已达借阅上限（N 册）"，用例结束，不进入第 5 步。
- 4b. 存在超期未还图书：系统列出超期书目与欠缴罚款，提示"请先归还超期图书"，用例结束。
- 7a. 同一条码已被借出：系统提示该副本当前状态与应还日期。

**异常事件流**

- 3a. 借阅证号不存在：系统提示"借阅证不存在"，用例结束。
- 3b. 借阅证状态为挂起/注销：系统提示当前状态与原因，用例结束。
- 6a. 馆藏条码不属于本馆：系统提示"非本馆藏书"，用例结束。
- 10a. 系统保存借阅记录失败（并发重复借出）：事务回滚，提示"操作冲突，请重试"。

### UC-102 办理还书 ★核心

- **主要参与者**：Librarian 图书管理员
- **前置条件**：图书管理员已登录；该副本处于"已借出"或"超期"状态
- **后置条件**（成功）：Loan 记录标记为已还；LibraryItem 状态变为"在馆"；若超期则生成 FineRecord
- **关联需求**：FR-007；业务规则 BR-008、BR-009、BR-013

**基本事件流**

1. 学生把所借图书交给图书管理员。
2. 图书管理员输入**馆藏条码**（还书不需要借阅证）。
3. 系统验证该图书为本馆藏书（BR-008），并定位到对应的在借 Loan 记录。
4. 系统判断应还日期与今日的关系，若已超期则执行 UC-903 计算超期罚款（BR-009）。
5. 系统删除（标记结清）相应的借阅信息，记录归还日期。
6. 系统更新副本状态为"在馆"，更新该学生账户。
7. 系统检查该读者是否有超期未归还的其他图书，若有则一并提示。
8. 系统显示还书结果；若产生罚款，显示罚款金额。

**备选事件流**

- 4a. 未超期：跳过罚款计算，直接进入第 5 步。
- 7a. 该读者名下还有其他超期图书：系统列出清单并提示。

**异常事件流**

- 3a. 条码不属于本馆：系统提示"非本馆藏书，无法办理归还"，用例结束。
- 3b. 该条码无对应的在借记录（副本状态为"在馆"）：系统提示"该副本未借出"，用例结束。
- 6a. 状态更新失败：事务回滚，提示"操作失败，请重试"。

### UC-003 预约图书 ★核心

- **主要参与者**：Reader 读者（学生或教师）
- **前置条件**：读者已注册；目标题名当前无可借副本
- **后置条件**（成功）：生成一条 Reservation 记录，进入该题名的预约队列
- **关联需求**：FR-003；业务规则 BR-010、BR-011、BR-012

**基本事件流**

1. 读者通过网络检索图书（UC-002），选择题名。
2. 读者提交预约请求。
3. 系统校验同一读者对同一题名无有效预约（BR-011）。
4. 系统按创建时间将该预约加入题名的预约队列（BR-010）。
5. 系统返回预约成功与该读者的排队位次。
6. 当有副本归还且该读者位于队首时，系统通知读者取书，预约保留 3 天（BR-012）。

**备选事件流**

- 2a. 该题名当前存在可借副本：系统提示"当前有可借副本，可直接借阅"，不创建预约。
- 6a. 读者未在 3 天内取书：预约失效，队列顺延给下一位并通知。

**异常事件流**

- 3a. 已存在有效预约：系统提示"您已预约该题名，排队位次 N"，用例结束。
- 1a. 读者账号未注册或无有效借阅证：系统提示先办理借阅证，用例结束。

### UC-201 办理借阅证 ★核心

- **主要参与者**：SystemAdmin 系统管理员
- **前置条件**：系统管理员已登录；读者已完成注册（UC-001）
- **后置条件**（成功）：生成 BorrowCard，证号唯一，状态 ACTIVE
- **关联需求**：FR-009；业务规则 BR-001、BR-003、BR-014

**基本事件流**

1. 系统管理员查询并选择已注册的读者。
2. 系统校验该读者当前无有效借阅证（BR-003）。
3. 系统按 `CARD + 年份 + 6 位序号` 生成借阅证号（BR-001）。
4. 系统创建借阅证，写入读者姓名、系别/单位、借阅证号，状态置为 ACTIVE。
5. 系统显示办证结果。

**备选事件流**

- 2a. 该读者已持有有效证：提示"该读者已持有借阅证"，用例结束。

**异常事件流**

- 1a. 读者未注册：提示"请先注册读者账号"，用例结束。
- 4a. 证号生成冲突（并发）：重试生成，仍失败则提示"系统繁忙"。

### UC-903 计算超期罚款 ★核心（被 UC-102 扩展）

- **主要参与者**：系统（定时或在还书时触发）
- **前置条件**：存在应还日期早于今日的在借记录
- **后置条件**：生成 FineRecord
- **关联需求**：FR-017；业务规则 BR-009

**基本事件流**

1. 系统取该借阅记录对应副本的**借出物类型**（中文图书 / 外文图书 / 杂志 / 论文）。
2. 系统按借出物类型取得对应的 FineRule（宽限期、每日罚金、单笔上限）。
3. 超期天数 = 今日 − 应还日期 − 宽限期（为负则取 0）。
4. 罚款金额 = 超期天数 × 每日罚金。
5. 若金额超过单笔上限，取上限值（BR-009）。
6. 生成罚款记录，状态"未缴"。

**备选事件流**

- 3a. 超期天数为 0（在宽限期内）：不生成罚款记录，用例结束。

**异常事件流**

- 2a. 找不到该借出物类型对应的罚款规则：记系统告警，按默认规则（中文图书）计算，
  并在罚款记录上标注"规则缺失，已按默认计算"，避免业务中断。

## 4. 用例关系说明

| 关系 | 表达 |
|---|---|
| `UC-101 ..> UC-901 : <<include>>` | 借书必须验证借阅证 |
| `UC-101 ..> UC-902 : <<include>>` | 借书必须检查借阅规则 |
| `UC-102 ..> UC-903 : <<extend>>` | 仅超期时才计算罚款 |
| `Student --|> Reader`、`Teacher --|> Reader` | 参与者泛化 |

>`UC-901 / UC-902 / UC-903` 是被复用或条件触发的公共行为，因此抽为独立用例；
>读者类型的差异**不做成独立用例**，由 UC-902 内部的 BorrowPolicy 处理，避免用例数量爆炸。
