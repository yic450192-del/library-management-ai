# 02 · 需求规格 Requirements

> 需求编号 FR / BR 会被用例文本回链。每条 FR 都带**可验证的验收标准**。
> 全部来自 Word 指导书第 56–69 行的功能性需求，不引入指导书之外的功能。

## 1. 参与者

| 编号 | 参与者 | 说明 |
|---|---|---|
| ACT-01 | Reader 读者 | 抽象读者，持有借阅证 |
| ACT-02 | Student 学生读者 | 本科生 / 研究生 / 博士生 / 专科生 |
| ACT-03 | Teacher 教师读者 | 教师 |
| ACT-04 | Librarian 图书管理员 | 读者代理，办理借还 |
| ACT-05 | SystemAdmin 系统管理员 | 系统维护 |

## 2. 功能需求

### 读者域

**FR-001 注册读者账号**
读者提交姓名、系别/单位、读者类型，系统创建账号。
- 验收：注册成功后生成唯一读者编号；同一姓名 + 系别 + 类型重复注册应被拒绝。

**FR-002 查询图书**
读者可按书名、作者、ISBN、题名类型检索题名及其可借副本数。
- 验收：命中题名列表，并标明可借副本数量；无命中时返回空列表而非错误。

**FR-003 预约图书**
读者通过网络对某题名预约，系统按创建时间排队。
- 验收：预约成功后返回排队位次；同题名多人预约按时间先后排序。

**FR-004 取消预约**
读者可取消自己尚未生效的预约。
- 验收：取消后队尾其后预约者位次前移。

**FR-005 查询借阅信息**
读者查询自己的在借记录、应还日期、超期情况与罚款。
- 验收：返回在借列表 + 历史列表 + 未缴罚款合计。

### 图书管理员域

**FR-006 办理借书**（指导书需求 2，核心用例）
管理员输入借阅证号与馆藏条码，系统验证后创建借阅记录。
- 验收 1：借阅证号不存在或非有效状态 → 拒绝并提示原因。
- 验收 2：在借数量已达该读者类型上限 → 拒绝。
- 验收 3：存在超期未还图书 → 拒绝。
- 验收 4：副本非本馆藏书或已在借 → 拒绝。
- 验收 5：全部通过 → 生成借阅记录，副本状态变为"已借出"，应还日期 = 借出日 + 该读者类型期限。

**FR-007 办理还书**（指导书需求 2，核心用例）
管理员输入馆藏条码，系统验证为本馆藏书后结清借阅记录。
- 验收 1：条码不属于本馆 → 拒绝。
- 验收 2：超期 → 按该借出物类型的罚款规则生成罚款记录。
- 验收 3：归还成功后副本状态变为"在馆"，借阅记录标记已还。

**FR-008 查询读者借阅信息**
管理员输入借阅证号，查询该读者的借阅与罚款情况。
- 验收：返回该读者在借记录、历史记录、未缴罚款。

### 系统管理员域

**FR-009 办理借阅证**
为已注册读者生成借阅证，含姓名、系别、借阅证号。
- 验收：一个读者至多一张有效借阅证；证号唯一。

**FR-010 删除借阅证**
- 验收：存在在借记录时拒绝删除；否则注销成功，证状态变为 CANCELLED。

**FR-011 添加图书管理员**
**FR-012 删除图书管理员**
- 验收：不能删除最后一名图书管理员。

**FR-013 添加图书 / FR-014 删除图书**（馆藏副本）
- 验收：删除时若副本在借中则拒绝。

**FR-015 添加标题信息 / FR-016 删除标题信息**（题名）
- 验收：题名下仍有副本时拒绝删除题名；题名 ISBN 唯一。

**FR-017 维护借阅规则与罚款规则**
- 验收：按读者类型配置最大数量与期限；按借出物类型配置罚金规则；修改后对**新产生的**借阅生效。

## 3. 业务规则

| 编号 | 规则 | 归属 |
|---|---|---|
| BR-001 | 借阅证号格式 `CARD + 年份 + 6 位序号`，全局唯一 | BorrowCard |
| BR-002 | 借阅证状态非 ACTIVE 时不得借书 | BorrowCard |
| BR-003 | 一个读者至多持有一张有效借阅证 | Reader / BorrowCard |
| BR-004 | 在借数量 = 该读者当前状态为"借出/超期"的借阅记录数 | Loan |
| BR-005 | 存在超期未还图书的读者不得再借 | Loan / BorrowPolicy |
| BR-006 | 应还日期 = 借出日期 + 该读者类型的借阅期限 | BorrowPolicy |
| BR-007 | 只有状态为"在馆"的副本可被借出 | LibraryItem |
| BR-008 | 归还的条码必须属于本馆馆藏 | LibraryItem |
| BR-009 | 罚款金额 = 超期天数 × 该借出物类型每日罚金，不超过单笔上限 | FineRule |
| BR-010 | 预约面向题名而非副本；同题名按创建时间排队 | Reservation |
| BR-011 | 同一读者对同一题名只能有一条有效预约 | Reservation |
| BR-012 | 预约保留 3 天，逾期失效并顺延给下一位 | Reservation |
| BR-013 | 借书、还书只能由图书管理员发起 | 权限 |
| BR-014 | 维护管理员、图书、题名、规则只能由系统管理员发起 | 权限 |
| BR-015 | 删除操作的前置校验：借阅证有在借 → 拒；副在在借 → 拒；题名有副本 → 拒 | 各聚合根 |

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-001 | 采用分层架构 + MVC，业务规则不得写在 Controller |
| NFR-002 | 借阅与罚款规则集中在 Policy / Rule 类中，不得散落 |
| NFR-003 | 领域层不依赖 Spring、不依赖持久化框架 |
| NFR-004 | 读者、管理员、系统管理员三类权限严格分离 |
| NFR-005 | 核心用例（借书、还书、预约、超期罚款、权限失败）必须有自动化测试 |
| NFR-006 | 所有 UML 以 PlantUML 文本保存并纳入 Git 版本管理 |
