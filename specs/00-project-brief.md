# 00 · Project Brief：图书管理系统

## 1. 项目背景

《软件设计与体系结构》课程实验项目。在既有 UML 建模结果的基础上提出更多要求，
完成架构设计（实验一）与详细设计（实验二）。

## 2. 业务概述（源自指导书原文）

学生要借书必须先在系统中注册账号，系统为其生成借阅证，借阅证提供学生姓名、系别、借阅证号。
持有借阅证的借阅者可以借阅图书、归还图书、查询借阅信息，**但这些操作都通过图书管理员代理与系统交互**。

借书时：学生找到图书 → 到借书处把借书证和图书交给图书管理员 → 管理员输入借书证号 →
系统验证借阅证是否有效（系统是否存在该证号对应的账户）→ 若有效，检验该账户中的借阅信息，
验证借阅的图书**是否超过规定数量**，或**是否有超过规定借阅期限而未归还的图书** →
通过验证后系统显示借阅者信息 → 管理员输入要借阅的图书信息 → 系统记录一条借阅信息，
并更新该学生账户。

还书时：学生把图书交给管理员 → 管理员输入图书信息 → 系统验证该图书**是否为本馆藏书** →
若是则删除相应的借阅信息并更新学生账户。还书时也会检验该学生是否有超期未归还图书。
学生也可以查询自己的借阅信息。

系统需要系统管理员进行系统维护。

## 3. 功能性需求（指导书给定的 7 条）

1. 学生持有借书证。
2. 图书管理员作为借阅者的代理完成借阅图书、归还图书和查询借阅信息工作。
3. 系统管理员完成对系统的维护：办理借阅证、删除借阅证、添加管理员、删除管理员、
   添加图书、删除图书、添加标题信息、删除标题信息。
4. 服务对象扩充到老师和学生；学生又分为博士生、研究生、本科生、专科生等，
   **不同类型的对象可以借阅的图书数量和期限都是不同的**。
5. 图书的种类扩充到中外文图书、中外文杂志、论文等。
6. 学生和老师**可以通过网络进行预约、查询**。
7. 超期罚款，**各种类型的借出物罚款规则不同**（超期时间的规定和罚金都不同）。

## 4. 参与者

| 参与者 | 说明 |
|---|---|
| Reader 读者 | 抽象参与者 |
| Student 学生读者 | 本科生 / 研究生 / 博士生 / 专科生 |
| Teacher 教师读者 | 教师 |
| Librarian 图书管理员 | 作为读者代理办理借书、还书、查询借阅信息 |
| SystemAdmin 系统管理员 | 系统维护 |

## 5. 技术要求

- 用 UML 表达分析与设计结果；
- 采用**分层架构**与 **MVC 模式**，以**包图**表达架构；
- 结合具体框架（Java EE / Spring）；
- 设计中体现 OO 设计原则与设计模式；
- 数据库设计以领域模型为基础，找出需持久化的类，转化为关系模型。

## 6. 暂不实现（本实验明确的边界）

- 真实支付/扣款，罚款仅登记不收款
- 条码扫描硬件集成
- 复杂全文检索（仅支持书名/作者/ISBN 精确与模糊匹配）
- 多校区馆藏调拨
- 微信 / 统一身份认证登录（实验一不实现真实认证，以角色标识代表操作人）
